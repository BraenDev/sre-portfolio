Background

I spent over a decade supporting Tyler Technologies' Enterprise Justice / Odyssey platform (2012–2025, remote) across SaaS and on-site customer environments — production incident response, application and server deployments, upgrades, and troubleshooting at scale. Most recently at AestheticsPro (2025–2026, remote), I handled production incidents on a Lucee-based web platform, including the manual runbook every on-call engineer knows: pull the node from the load balancer, restart services, verify health, return it to traffic, notify stakeholders.

That toil is exactly what SRE exists to eliminate — and this site is where I prove I can eliminate it. Core stack: VMware vSphere, Windows Server, Active Directory / Entra ID, Cisco networking and firewalls, NetApp and Dell storage, Veeam, SIEM (LevelBlue/AlienVault), Datadog, and scripting in PowerShell, Python, and Bash. The labs here add Kubernetes, Terraform, Prometheus/Grafana, and CI/CD on top of that foundation.

How this portfolio works

Evidence over claims

No skills lists. Every project shows the problem, the architecture, the code, the failure test, how it was detected, how it recovered — and the metrics that prove it.

Lab work is labeled lab work

Nothing here pretends a home lab was a production outage. Implementations are framed as what they are: "implemented in my SRE lab to demonstrate…"

Production-readiness, assessed

Each project closes with what would have to change before real production: redundancy, secrets management, TLS, backup testing, load testing. Judgment is the deliverable.

Explore

Project pages follow one template: problem → architecture → implementation → failure test → detection → recovery → verification → lessons → production-readiness.

How pages get published

  1. Learn — one primary resource per technology, no tutorial hoarding.
  2. Build — a working lab system, committed to GitHub.
  3. Break — a controlled, intentional failure.
  4. Troubleshoot — detect, diagnose, recover, measure.
  5. Document — runbook and postmortem, written like production.
  6. Publish — a project page here, following the template.

The site grows as SRE study quests complete. The long-term capstone — Project RELIQUARY — will integrate Terraform, Kubernetes, CI/CD, observability, SLOs, and automated remediation into one platform.
